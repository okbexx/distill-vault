# 个人工作台：第一版边界

桌面端是独立 Obsidian 工作台；Agent 从 CLI/MCP 读写同一份非秘密资料，不内嵌聊天。

## 内容约定

- 收件箱：允许无项目、未完成、疑问与混合想法，原文优先。整理和晋升不是保存前提。
- 项目：保存入口、环境、配置位置、启动和验证流程、注意事项。操作说明不是待办。历史来源不因页面简化而删除。
- 访问资料：只保存服务、环境、账号标识、凭据引用、存储方式、认证方式、验证说明。秘密在外部密码管理器中，不进入 Markdown、Git、搜索索引或 Agent 默认上下文。
- 文档日期区分 edited/updated 与 verified_at；编辑不代表重新验证。
- 标题与关联是帮助检索的元数据，不以填满固定生命周期章节为验收标准。

## 改动边界

开发验证在独立分支进行；安装引擎不自动迁移资料或修改定时任务，实例部署按明确授权执行。旧 capture 的已完成事实路径保持兼容；新增轻量收件接口承担自由输入。

规范调整应同步到实例，不能一边放宽输入，一边继续用旧 schema 拒绝它。示例库用于隔离验证；真实实例需同步检查现行规则和配置，示例通过不代替实例验收。

## 后续自动化迁移规则

日报只有非运维内容变化时才生成。巡检只在发现新问题或问题状态变化时写报告；无变化不刷新项目 updated、不产生提交。Git commit 日期不作为知识变化的唯一证据。调度器配置与实际运行验收独立记录，安装引擎不代表调度器已切换或通过验证。

## 验收

1. 任意文字可保存，无项目也成功，附件保留字节内容。
2. 同名记录和附件不覆盖，越界路径被拒绝。
3. 修改指定文件时仅因触及内容的问题而阻断；全库检查仍可显式执行。
4. 工作台离线可浏览、编辑、搜索，不需要模型。
5. 项目入口和访问资料可从 Markdown 恢复，不依赖插件私有数据库。
6. macOS 原生 Obsidian 的交互、协议链接与快捷键需在 Mac 验收；Linux 构建或模拟测试不代替该验收。

## 新增引擎入口

- `distill -v <vault> record "任意临时文字" --format json`：不要求项目归属；不替代原有已完成事实 `capture`。
- `--attachment <file>` 可重复指定，复制用户明确选择的附件，不自动读取凭据文件。
- MCP `source_record` 调用同一实现。Agent 从结果取得来源路径与受影响文件集合。
- `distill lint --paths <path>` 与 `distill commit --paths <path> --skip-run` 用于局部验证和提交；全库命令仍保留。
- 原文有独立副本时，该副本代表最初输入；后续笔记编辑代表整理版本，两者不假称实时双向同步。

### Agent 工作流约定

- 返回的提交命令明确包含 `--vault`，可从其他项目目录执行；路径、标题和消息按 shell 参数引用，方括号文件名按 Git literal pathspec 提交，不作通配展开。
- 用 `capture.source_dir` 明确指定轻量收件目录。其内未声明稳定类型或状态的桌面笔记按 raw source 读取，不修改磁盘原文；显式稳定对象仍须通过原有关系和结构检查。
- `source_record` 的 `source.md` 用 `attachments` 清单标记同目录编号附件。Markdown 附件的整份字节是原文，不把其中的 YAML、ID 或 wiki 引用提升为对象元数据与关系。旧版本生成的 bundle 仅在匹配原生成器格式时兼容识别。
- raw 正文不产生已整理图关系；显式 frontmatter 关系仍校验。`lint --fix` 不改写 raw 原文，稳定对象不因位于收件目录而自动豁免。
- `scripts/verify_agent_workflow.py` 用真实 MCP stdio 在临时库复测五条链路，任一失败即非零退出；可用 `--config-from <vault>` 只复制配置与 schema，不复制真实内容。它是接口链路测试，不等于自然语言 Agent 或桌面 GUI 验收。

不要把密码作为命令行参数、笔记内容或附件传入本功能。新入口不是秘密存储器。

## 回退

示例库独立于真实库；停用插件不会删除笔记和附件。部署前记录原引擎提交与实例分支，开发阶段可丢弃独立分支；已经部署后的回退需分别处理引擎版本与资料变更，不将新写入的资料一起丢弃。真实迁移在 Git 分支上进行，不覆盖原库。

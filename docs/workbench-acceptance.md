# 验收清单

## 本地自动验收

- 引擎：自由文本和仅附件输入保存成功，原文不被正文模板改写。
- 安全：路径穿越、符号链接越界、重复文件名不会覆盖用户内容；引擎保存失败回滚本次bundle。插件部分附件写入后失败会报告保留路径并保留窗口草稿，不假称整体保存成功。
- 兼容：原先的项目事实 capture 行为保持；CLI 和 MCP 采用同一个实现。
- 提交：局部错误阻止局部提交，无关历史错误不阻止；显式全库检查仍有效。
- 索引：原始收件记录可被搜索；未关联项目只是整理状态，不作为稳定知识缺陷。
- 插件：构建成功，输入和写入逻辑有行为测试，产物含 manifest/main.js/styles.css。
- 分发：只打包公开示例；不得复制真实知识库、密码、缓存、索引或个人配置。

## Agent 链路验收

- 运行 `PYTHONPATH=. .venv/bin/python scripts/verify_agent_workflow.py --config-from <vault> --output <report.json>`；只拷贝配置/schema到临时fixture，不拷贝真实正文。
- 从其他项目目录执行返回的提交命令；文字/附件可找回，提交不夹带无关文件。
- 方括号附件名可以字面提交，路径越界/Git magic/危险删除仍失败。
- 桌面手写raw笔记、含未整理wiki引用甚至坏YAML的Markdown附件可以保存、检索和提交；原始字节不变，附件内ID/关系不进入稳定图谱。
- 同目录显式稳定对象仍检查schema/断链；raw的显式frontmatter关系仍校验。
- 自然语言Agent另做独立验收：无项目的未来想法记录、只读查询、一处修订保留原文、附件缺失不误报成功。由真实模型选择工具，以磁盘和Git结果判定，不以Agent自报或脚本预定调用顺序代替。

## macOS Obsidian 验收（必须标为待验，不能用 Linux 测试代替）

1. 解压独立库，在 Obsidian 打开。审阅插件代码后手动启用插件；分发包不强行启用第三方代码。
2. 命令面板打开工作台；主页、收件箱、项目、访问资料能跳转。
3. 快捷记录中输入两行文字并粘贴一张截图；保存后图片可见、内容可编辑。
4. 保存同名附件两次，第一份不能被覆盖。
5. 用全局搜索查找刚保存的文字并打开原文。
6. 项目环境和注意事项清楚可读，打开外部地址不执行shell命令。
7. 访问资料仅出现外部凭据引用；关闭 Agent 仍可使用。
8. 关闭并重开应用后内容仍在。停用插件后文件仍可读可编辑。

## 真实库迁移前置条件

- 此阶段不处理真实密码，也不自动扫描和收集秘密。
- 先对源库执行 preview_workbench.py 获取只读库存。
- 在副本或独立 Git 分支适配输入契约，确认旧 schema/规范不会重新强制整理。
- 逐项目去重页面展示，保留来源原文与验证证据；不按批量文本替换抹去历史。
- 迁移方案单独确认后再写入原库、调整自动化与部署引擎。

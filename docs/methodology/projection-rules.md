# 对话输入到对象投影规则

## 目的

定义用户直接通过对话输入内容时，private acceptance vault 应如何自动整理到对象层，而不是要求用户手写旧目录文件。

## 总原则

- 新内容默认不再写入 `记录/`、`日报/`、`周报/`、`碎碎念/`、`风格/`。
- 这些历史目录已迁入 `兼容层/`，只读，不再承接新增内容。
- 新输入默认先成为来源对象，再投影到输出、项目、决策、约束、实体等对象。
- 默认遵循 [[知识/概念/满足质量要求的最短路径]]，优先做足够好的最小投影，不制造不必要的中间层。

## 默认投影流程

1. 识别输入类型
   - 日报 / 周报 / 阶段汇报
   - 普通来源
   - 候选概念来源
   - 已完成事实或项目成果
   - 约束或决策信号

2. 创建来源对象
   - 位置：`知识/来源/*`
   - `source_type` 优先使用 `conversation`
   - 保留原始输入的主要语义

3. 识别对象
   - 项目
   - 实体
   - 决策
   - 约束
   - 输出类型

4. 投影到目标对象
   - 日报 / 周报 -> `输出/*`
   - 已完成成果与长期上下文 -> `知识/项目/*`
   - 明确限制 -> `知识/约束/*`
   - 明确取舍 -> `知识/决策/*`
   - 人、团队、系统、工具 -> `知识/实体/*`
   - 稳定抽象 -> 先入 `运维/队列/晋升队列.md` 或直接入 `知识/概念/*`

5. 回刷目标对象（项目/实体/决策/约束等）
   - 任何投影动作**必须同步回刷目标对象的 `updated` 字段为当前日期**。
   - 项目只吸收已经完成或验证的事实，并更新 `summary` 或正文中的“已完成成果”。
   - 下一步、计划、待办、优先级和截止时间保留在日程工具，不投影到知识库。
   - 若新内容为目标对象新增了 `sources`/`decisions`/`constraints`/`key_outputs` 条目，同步追加到 frontmatter 对应列表。
   - 这是**强制步骤**，不是可选优化。跳过此步会导致对象过期堆积。

6. 同步运维
   - 更新 `运维/索引/总索引.md`
   - 更新 `运维/日志/知识库日志.md`
   - 必要时更新 `运维/健康检查/健康报告.md`

## 何时直接落地

满足以下条件时，优先直接更新对象，不额外制造候选层：

- 目标对象明确
- 来源明确
- 风险低
- 不涉及高层规则或长期抽象边界判断

## 何时进入晋升队列

满足以下任一条件时，先进入 `运维/队列/晋升队列.md`：

- 概念名称或边界不稳定
- 需要人工价值判断
- 与现有稳定对象可能冲突
- 影响范围大
- 证据仍不足

## 旧目录策略

- `兼容层/记录/`：历史方法池与待补投影来源
- `兼容层/日报/` / `兼容层/周报/`：历史输出与时间流来源
- `兼容层/碎碎念/`：历史候选来源
- `兼容层/风格/`：历史风格来源与资产

从本规则生效后，不再将新增内容直接写入这些目录。

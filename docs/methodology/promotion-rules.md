# 晋升规则

## 目的

- 定义什么内容可以从原始资料、会话或输出晋升为稳定知识对象。
- 阻止系统被一次性聊天和低质量总结污染。

## 总原则

不是所有输入、分析和回答都值得沉淀。
只有满足复用价值、来源明确、语义稳定的内容，才允许晋升。

## 路径原则

- 默认遵循“满足质量要求的最短路径”。
- 若已有清晰目标对象、来源明确、风险较低，则优先直接更新目标对象，不额外制造分析层、队列层或中间对象。
- 只有在以下情形下才升级流程强度：
  - 高影响长期规则变更
  - 与稳定对象冲突
  - 证据不足
  - 抽象名称或边界仍不清晰
  - 需要人工价值判断

## 允许的晋升路径

- 来源 -> 项目更新
- 来源 -> 概念
- 来源 -> 决策
- 来源 -> 约束
- 会话 -> 输出
- 输出 -> 概念
- 输出 -> 决策
- 输出 -> 约束

## 晋升到概念

必须同时满足：

- 能被复用于多个场景。
- 不只是一次性项目细节。
- 有明确来源或稳定经验基础。
- 能用一句清晰定义表达。
- 不与现有概念冲突，或已说明关系。

## 晋升到决策

必须同时满足：

- 存在明确取舍结果。
- 有具体上下文。
- 能说明原因。
- 能定位影响范围。
- 不是纯讨论中的备选项。

## 晋升到约束

必须同时满足：

- 是真实存在的限制、坑或边界。
- 已在实践中出现，或由高可信来源明确给出。
- 能说明忽略后的风险。
- 能说明 workaround 或当前无解状态。

## 晋升到项目更新

满足以下任一即可：

- 新增已完成成果或已验证里程碑
- 引入关键来源
- 新增关键决策
- 新增关键约束
- 生成关键输出

项目更新不得包含下一步、计划、待办、优先级或截止时间。

## 默认不晋升的内容

- 一次性情绪表达
- 低信息密度聊天
- 未经验证的猜测
- 没有来源的结论
- 为回答当前问题临时拼出的长文本
- 与已有对象高度重复且无新增信息的内容

## 提案、审核与应用

语义判断由 Agent 草拟，确定性边界由 Distill 执行：

1. Agent 生成完整概念、决策或约束对象。
2. `promotion_review` 检查来源、目标类型、schema、重复标题/ID 和写入路径。
3. 人确认或修改提案；review 本身不写文件。
4. `promotion_apply` 写入目标对象并补来源回链。
5. 再执行 lint 和 Git checkpoint，形成可撤销审计记录。

`distill promote --auto` 只能应用 `auto_safe=true` 的确定性动作，不能绕过不安全提案确认。

## 晋升后的必做动作

- 更新目标对象
- 让动态浏览面和图投影能够发现新对象
- 由 Git 保存审计轨迹

仅在必要时还要：

- 在高影响或冲突场景保留显式提案
- 标记 `supersedes`
- 生成待人工确认项

## 冲突规则

若新内容与稳定对象冲突，不得静默覆盖。
必须执行以下之一：

- 标注冲突证据
- 写入 superseding proposal
- 进入评审或晋升队列

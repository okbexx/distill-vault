# 定义
RAG 是把外部知识检索结果注入生成过程的一种应用模式，目标是让模型回答更贴近上下文、可追溯且可更新。对我而言，[[RAG（检索增强生成）]] 不是单一算法，而是一组围绕召回、重排、上下文拼接和回答验证的工程实践。

# 关键观察
- 在 [[AI客服助手]] 中，RAG 用来降低幻觉并承接频繁变化的运营知识。
- 在 [[智能文档平台]] 中，RAG 与 [[知识图谱]] 结合后，比纯向量召回更容易控制证据链。
- RAG 的效果高度依赖底层 [[向量数据库]] 的索引能力、元数据过滤和延迟表现。
- 当系统引入 [[Agent]] 时，RAG 不再只是“查一次再答”，而会变成多轮计划中的取证环节。

# 实践要点
1. 先定义问题类型，再决定是否需要图谱检索、关键词检索或向量检索。
2. 给检索结果附带来源片段，方便输出到 [[RAG技术选型报告]]。
3. 将检索失败案例沉淀到 [[所有AI接口必须做内容审核]] 与 [[数据不出境]] 的约束评估中。

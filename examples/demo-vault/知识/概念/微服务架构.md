# 定义
[[微服务架构]] 是将系统拆分为多个围绕业务能力构建的小服务，并通过稳定接口协作的架构方式。它强调边界清晰、独立部署和局部演进。

# 在当前知识库中的位置
- [[推荐系统优化]] 依赖微服务架构来隔离召回、排序、特征服务和实验平台。
- [[内部工具链]] 也在思考是否通过 Agent 管理分散的工具服务。
- [[2024-06-01 微服务架构最佳实践]] 提醒我，拆分服务前要先理解调用链和组织边界。

# 风险
- 服务拆得太细会让调用链复杂化，影响上线速度。
- 如果没有好的可观测性，微服务会放大排障成本，进而冲击 [[所有AI接口必须做内容审核]] 的落地效率。

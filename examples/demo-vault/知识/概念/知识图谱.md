# 定义
[[知识图谱]] 是把实体、概念、事件和关系显式建模的知识组织方式。它的价值不在于“有图”，而在于可解释的结构化连接。

# 应用场景
- [[智能文档平台]] 用图谱表达文档、术语、负责人和业务系统之间的关系。
- 在 [[RAG（检索增强生成）]] 中，图谱适合补足多跳查询与关系约束。
- 图谱还能帮助 [[内部工具链]] 做对象影响分析，减少因为隐性依赖造成的误判。

# 经验总结
- 不是所有问题都需要图谱；如果只是 FAQ 检索，[[向量数据库]] 可能更简单。
- 一旦涉及审批链、产品依赖或跨系统实体映射，图谱会明显优于纯向量。
- 图谱节点要尽量复用像 [[Anthropic]]、[[LangChain]]、[[Milvus]] 这样的实体对象。
